# Using story records

These examples build on the Marrow Street Station practice project in [Connect and start](../../README.md#connect-and-start). Substitute records from your own project when you are ready.

## Find a record and check its evidence

Ask **“Find scenes at Marrow Street Station. Show the saved passage or relationship that connects each one to the station.”** Search can match exact wording or meaning. A passage that mentions the station and a saved link that places a scene there are different kinds of evidence. Open the returned record in Workspace and inspect its **Relationships**.

Open the Relationship Graph to follow the station’s links to people, scenes, or organizations. Select a record and choose **Focus and expand** to see its neighbors. Select an edge to inspect the recorded relationship. If your question depends on an earlier draft, ask for the record’s history and identify the version you want to check.

## Compare what happened with who knew

1. Record an event in the practice project, for example a key moving from the ticket office to the platform. Save the event order and the change of location. When you want a scene to establish the time, identify the event that anchors it.
2. Record any witness’s observation, a character’s belief, and the scene that reveals the information to the audience. A witness can attend the event without seeing the key move. If you only know that a character held a belief **by** an event, record that boundary.
3. Ask **“At this scene, where was the key, what did the witness believe, and what had the audience learned? Show the evidence for each.”** Use **Story state context** in Workspace to select a scene, event, or perspective. Open **Why is this here?** to inspect the basis for a state item. When the saved chronology is ambiguous, the answer can stay unresolved.

The Timeline shows events in story order and keeps unplaced events visible. Open **Effects** on an event to see its participants, changes, and available perspective evidence. A later disclosure can tell the audience about an event long after it occurred.

## Work with images

Supply an image in your chat host and ask StoryRoom to save it and link it to a record. For example, link a station reference to Marrow Street Station, describe the viewpoint and lighting, and mark the ticket-office window as a region. For a character portrait, ask the assistant to assign the exact saved version as that character’s Workspace profile image.

Ask to find images by title, description, linked record, or visual similarity. For a similarity search, name a saved image and version to compare. Open the returned version to inspect the image or region before using it as evidence. A visually similar image can be a reference without documenting the same place or event.

## Assemble and export a screenplay

1. Save a scene draft. Use an **archival** assembly to preserve the drafts you imported, a **working** assembly to collect drafts in progress, or an **approved** assembly when every selected scene version has active approval.
2. Name the scenes in reading order and specify their versions. For example, ask **“Save a working assembly with version 2 of Warm Air first and version 1 of Ticket Office second.”** Use version numbers from your project. A saved assembly keeps those exact drafts when later revisions arrive.
3. Export the selected assembly version as plain text or JSON. If the included drafts use Fountain, you can also export them as Fountain. To change the reading order or include a revision, create another assembly version.

For the tools behind these steps, see the [tool reference](../storyroom-tools.md).
